A worked example

One decision, start to finish.

A holiday weekend. Illustrative, using the simulation’s rules: Joburg to Cape Town, base fare R1,000, Normal cap +10%, Surge cap +40%.

1

Engine proposes

The pricing engine asks for R1,400 on a busy route. That is +40% on the R1,000 base.

2

Steward rules

Normal cap is +10%, so the limit is R1,100. R1,400 is above it.

DENY · PR-1
3

Seal records

A Warrant is sealed with the ruling and the rule. The refusal now waits for a person.

4

Manager decides

The manager declares Surge for the weekend. The same R1,400 is now inside the cap.

5

Result, explained

Admit under PR-2, cap R1,400, sealed as a new Warrant. The Advocate explains it with every number checked.

ADMIT · PR-2

Our choices

Why it is built this way.

Judge apart from calculate.
Engines only propose. One Steward holds the Charter, so no engine can bypass a rule, and engines can be swapped without touching the rules.
Record first, explain after.
The Warrant is sealed before any words are written, so an explanation can never change what happened.
The AI explains, it never decides.
Every number it writes is checked against the record. If a check fails, or the model is down, a fixed template is used.
Built where the data lives.
Progress OpenEdge ABL transactions give the Seal its all-or-nothing writes. The browser displays only show what the simulation produces.
